# Map-Reflect: supplementary software

Code for "Map-Reflect: Uncertainty-Guided Reflection for Schema Mapping" (anonymous submission). It contains the
method (first pass, second pass, selection), the scorer, the statistics and the generators of the paper's numbers,
tables and figures. The companion archive `data.zip` holds the dataset inputs, the frozen configuration and the
stored model outputs.

Unzip `software.zip` and `data.zip` into the same directory. Both mirror one repository layout, so the paths in the
code resolve without changes.
Both archives carry a README.md at their root, so unzip the second without it:
`unzip software.zip -d supp && unzip data.zip -x README.md -d supp`.

## Environment

Python 3.13. `pip install -r requirements.txt`. Scoring needs only the first block (numpy, scipy, scikit-learn,
matplotlib, networkx, tqdm, python-dotenv); importing the runner also needs `openai` and `rank-bm25`, which are
only exercised when a model is called.

## Scoring from stored outputs (no model call)

From the directory where both archives were unzipped:

```
SUPP_DATASETS=toolbench,nl2gql,omop_cms,omop_synthea,valentine_chembl,valentine_opendata,valentine_tpcdi,valentine_wikidata,oaei_conference \
V5_FROZEN_COMMIT=frozen \
python scripts/naacl/v5.py --stage score
```

This applies the frozen v5 configuration (`docs/naacl/results/v5_frozen.json`: the benefit model's coefficients,
standardisation and threshold tau; the margin thresholds) to the stored first-pass and second-pass outcomes, scores
every field with `eval.calc_accuracy.target_correct`, and prints the policy table (first pass, Map-Reflect,
margin, schema-size rule, every field, random, oracle, the reference configuration) with split-group bootstrap
intervals, then the per-model and per-dataset gains and the held-out block. Output goes to `supp_out/` and never
overwrites the stored `docs/naacl/results/v5_facts.json`. It takes about a minute.

What to compare. The per-dataset lines (gain over the first pass for Map-Reflect, the reference configuration, the
schema-size rule and every field) equal the corresponding lines of the stored `docs/naacl/results/v5_test.md`
exactly, since each dataset's fields are scored independently. The pooled rows and intervals differ from the paper,
because the pooled population here leaves out the datasets that are not redistributed (see `data.zip`'s README).

Two small changes against the authors' copy, both in `scripts/naacl/v5.py`, make this possible: `SUPP_DATASETS`
restricts loading and scoring to the datasets present (the frozen model still carries all ten dataset indicators),
and a missing ITOpsGraph label file is tolerated when ITOpsGraph is not scored. `V5_FROZEN_COMMIT` replaces the
check that the frozen file is committed in version control, which an unzipped copy cannot do.

## Regenerating every table and number

`scripts/naacl/v6_numbers.py` regenerates `paper/numbers_v6.tex`, `docs/naacl/v6/FACTS.md`, the `paper/tab6_*.tex`
tables and the chart data in one run. It reads the complete stored-output tree (about 12 GB: every ablation, the
reference configuration on development and test, the baselines and the held-out runs) and the full set of
datasets, so it cannot run from these archives alone. The generated outputs it produced are in `data.zip`
(`paper/numbers_v6.tex`, `paper/tab6_*.tex`, `paper/figures/data6/*.csv`, `docs/naacl/v6/FACTS.md`), so every
number in the paper can be traced to its fact identifier, claim, value, interval, source file and generating
function.

## Running the method (model calls)

```
cp .env.example .env    # fill in ENDPOINT_A and ENDPOINT_B
bash scripts/naacl/v6_calls/run_v5.sh <gptoss|qwen35|llama4|granite> <dev|test>
```

`run_v5.sh` runs the second pass over the stored first pass. The first pass is
`map_reflect/map_reflect_runner.py` with the datasets in `data/`. Endpoints are anonymised: ENDPOINT_A is an
OpenAI-compatible chat gateway (gpt-oss-120b, Qwen3.5-397B-A17B, a copy of Granite-4), ENDPOINT_B a hosted
text-generation service (Llama-4 Maverick, Granite-4) whose Python SDK is imported here as `endpoint_b_sdk`, and
ENDPOINT_C a LiteLLM gateway used only for optional checks. The clients are `EndpointABatchClient` and
`EndpointBBatchClient`. To run against another OpenAI-compatible server, set `ENDPOINT_A_URL` and use the
`endpoint_a/<org>/<model>` model prefix. The decoding settings are in the appendix (Models and decoding).
`scripts/naacl/v6_calls/endpoint_b_throttle.py` shares one request-rate limit across processes for ENDPOINT_B.

## What is not included, and why

* Baseline systems of Table 1 (MatchMaker, AnyTool, Magneto, Cupid, Similarity Flooding, Prompt-Matcher) and
  their runners: they are third-party systems or faithful reimplementations, and their stored scores are in the
  facts ledger.
* Research code not used by the reported results (earlier method versions, notebooks, graph-model experiments),
  deployment code, services and user interfaces.
* Tests and internal review tooling.
